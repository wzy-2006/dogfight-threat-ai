# 需求分析

> 依据《湖北省大学生创新训练计划申请书 —— 基于实时威胁评估与动态决策的飞机对战游戏》
> 编写。本文只定义**第一阶段（V1）**要实现并验收的需求；第二阶段的网络联机需求列在文末。
>
> 关联：[系统设计](../02-design/系统设计.md) · [用户手册](../04-manuals/用户手册.md)

---

## 一、项目背景与问题定义

立项书指出市面 2D 空战游戏存在三个短板：

| 短板 | 具体表现 | 本项目的应对 |
|---|---|---|
| 交互浅 | 八方向移动、无惯性、静态背景 | 物理飞行模型 + 多层视差场景 |
| AI 笨 | 固定航线、行为可被摸透、难度靠加数值 | 实时威胁评估 + 动态行为决策，三档靠算法质量区分 |
| 只能单机 | 缺实时对战、观战、社交 | 第二阶段的三层网络架构 |

第一阶段的目标是**先把前两条做扎实**，并搭好第三条的架构地基。

## 二、涉众与使用场景

| 涉众 | 关注点 |
|---|---|
| 玩家 | 操控手感、打击反馈、对手是否"像人"、难度是否可调 |
| 项目成员（开发者） | 模块是否可独立开发与测试、算法是否可单独验证 |
| 指导教师 | 技术路线是否清晰、算法创新点是否可演示 |
| 答辩评委 | 能否当场演示、核心机制能否被直观看到 |

### 典型场景

| 编号 | 场景 | 期望 |
|---|---|---|
| UC-01 | 玩家首次运行 | 不需要手工配置素材与引用，打开工程按 Play 即可开打 |
| UC-02 | 玩家操控战机 | 有惯性与阻尼，速度影响操控性，和"八方向移动"手感明显不同 |
| UC-03 | 玩家与敌机交战 | 机炮/导弹有不同手感与代价，命中反馈清晰 |
| UC-04 | 玩家被 AI 咬尾 | AI 会追击、会提前量瞄准，玩家能靠减速板/规避摆脱 |
| UC-05 | 玩家观察 AI | 能直观看到 AI 如何评估战场威胁（威胁网格可视化） |
| UC-06 | 玩家调难度 | 三档 AI 手感差异明显，且可微调算法参数 |
| UC-07 | 开发者改算法 | 改完能立刻验证没写坏，不必打开 Unity 逐帧试玩 |
| UC-08 | 答辩演示 | 能在 30 秒内展示"AI 因为威胁升高而切换行为" |

## 三、功能需求

### FR-1 二维空战场景与交互

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-1.1 | 多层视差背景 | 高 | ≥3 个图层，各自独立视差系数；平铺无缝，看不到接缝 |
| FR-1.2 | 战机精灵渲染 | 高 | 32×32 像素画按 PPU=32 渲染，Point 过滤不糊 |
| FR-1.3 | 场景边界判定 | 高 | 出界有回推与告警，不会飞出场景消失 |
| FR-1.4 | 相机跟随 | 中 | 平滑跟随 + 速度前瞻，高速时不"甩镜头" |

### FR-2 飞行动力学

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-2.1 | 油门加减速 | 高 | W/S 改变推力，加速收敛到上限，不超过上限 |
| FR-2.2 | **惯性滑行** | 高 | 收油门后不会立刻停下，靠阻尼衰减 |
| FR-2.3 | **转向阻尼** | 高 | 松杆后角速度趋近 0；转向有过渡不突变 |
| FR-2.4 | **舵效随速度变化** | 高 | 低速舵效显著低于高速，低于最小速度视为失速 |
| FR-2.5 | 速度边界约束 | 高 | 速度恒在 [minSpeed, maxSpeed] 内 |
| FR-2.6 | 减速板 | 中 | 提供额外阻力，用于摆脱咬尾 |

> 验收方式：`CoreSelfTest` 中「飞行物理」8 项自动断言覆盖 FR-2.1~FR-2.6。

### FR-3 武器系统

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-3.1 | 机炮 | 高 | 有冷却、有散布、弹丸继承载机速度 |
| FR-3.2 | 机炮过热 | 中 | 持续开火约 4.9 秒触发过热并锁定，散热后恢复 |
| FR-3.3 | 导弹锁定 | 高 | 锥角内按住累积进度，满进度自动发射 |
| FR-3.4 | 导弹制导 | 高 | 导引头有最大转弯率；离架后有解锁延迟 |
| FR-3.5 | 近炸引信 | 中 | 靠近目标即引爆 |
| FR-3.6 | 无制导发射 | 低 | 未锁定松手时发射无制导弹 |

### FR-4 碰撞与战斗反馈

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-4.1 | 弹丸命中判定 | 高 | 用扫掠检测，**高速弹不得穿透** |
| FR-4.2 | 敌我识别 | 高 | 默认同队不互伤；不命中发射者自己 |
| FR-4.3 | 撞机判定 | 中 | 双方受伤并被弹开 |
| FR-4.4 | 伤害与击落 | 高 | 血量归零触发爆炸、计分、连击 |
| FR-4.5 | 命中反馈 | 中 | 受击闪白 + 火花 + 屏幕抖动 |

### FR-5 实时威胁评估与动态决策 AI ★

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-5.1 | 威胁指标计算 | 高 | 由距离/相对方位/闭合率/武器威胁/我方状态五因子加权；取值恒在 [0,1] |
| FR-5.2 | 单调性 | 高 | 越近、对方越对冲、我方血越少 → 威胁越高 |
| FR-5.3 | 网格化战场建模 | 高 | 网格逐帧累加并衰减；半径外为 0；支持采样与梯度 |
| FR-5.4 | 五种行为模式 | 高 | 巡逻/搜索/追击/攻击/规避，能自主切换 |
| FR-5.5 | 切换稳定性 | 中 | 带滞回，不在阈值附近抖动 |
| FR-5.6 | BFS 目标搜索 | 高 | 能找到最近的未侦察格子并返回路径 |
| FR-5.7 | A\* 路径规划 | 高 | 能绕开高威胁区域到达目标 |
| FR-5.8 | 三档难度 | 高 | 反应时间/瞄准误差/提前量/规避阈值/导弹技巧/是否用 A\* 规划 |
| FR-5.9 | 威胁可视化 | 中 | 能把威胁网格叠加显示出来（答辩演示用） |

> 验收方式：`CoreSelfTest` 中「威胁评估」8 项 +「路径规划」6 项自动断言覆盖。

### FR-6 多层级雷达与 HUD

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-6.1 | 三层雷达 | 高 | 近/中/远三个量程环，目标按类型与威胁着色 |
| FR-6.2 | 雷达扫描线 | 低 | 有视觉扫描效果 |
| FR-6.3 | 来袭告警 | 高 | 被导弹锁定时雷达闪烁 + 屏幕告警 |
| FR-6.4 | 状态面板 | 高 | 血量/油门/空速/机炮过热/导弹弹药 |
| FR-6.5 | 战果面板 | 中 | 波次/敌机数/得分/击落/连击/FPS |
| FR-6.6 | 结算面板 | 中 | 得分/击落/命中率/最高连杀/承受伤害/存活时间 |

### FR-7 波次与关卡

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-7.1 | 波次生成 | 高 | 数量随波次单调递增；由规则算出而非死表 |
| FR-7.2 | 机型解锁 | 中 | 高级机型按波次解锁（第 1 波不出现重型机） |
| FR-7.3 | 属性成长与上限 | 中 | 血量/伤害/速度随波次成长但有硬上限 |
| FR-7.4 | 入场阵型 | 低 | 至少 3 种阵型，从场地边缘进入 |
| FR-7.5 | 玩家复活 | 中 | 3 条命，死亡后按游戏时间倒计时复活 |

> FR-7.5 特别要求：复活倒计时必须用**游戏时间**而非 `setTimeout`，
> 否则快进/暂停/无头测试时行为不一致。

### FR-8 工程与可维护性

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-8.1 | 数值集中可配 | 高 | 所有平衡性常量集中在 `ConfigDefaults`，代码里不写死 |
| FR-8.2 | 运行时调参 | 中 | `GameConfig` 资源可在 Inspector 调 AI 参数 |
| FR-8.3 | 算法可独立验证 | 高 | 不开 Unity 也能编译并跑核心自检 |
| FR-8.4 | 一键搭建 | 高 | 菜单一次点击完成素材配置 + 资源生成 + 建场景 |
| FR-8.5 | 素材降级 | 中 | 素材缺失时用程序化占位图，不白屏 |
| FR-8.6 | 可扩展点 | 中 | 规划器/行为/机型/武器/AI 档位都能"加一条数据"扩展 |

## 四、非功能需求

| 编号 | 类别 | 需求 | 验收标准 |
|---|---|---|---|
| NFR-1 | 性能 | 稳定 60 FPS | 同屏 ≤14 架敌机 + 数十弹丸时帧率不低于 55 |
| NFR-2 | 性能 | 仿真与帧率解耦 | 固定 1/120 步长；卡顿不导致物理爆炸 |
| NFR-3 | 可复现 | 同种子同结果 | 给定 seed 与输入序列，仿真结果完全一致 |
| NFR-4 | 可移植 | Core 无引擎依赖 | `Dogfight.Core` 程序集 `noEngineReferences = true` 可编译 |
| NFR-5 | 可维护 | 代码风格统一 | 符合 `.editorconfig`（Allman、4 空格、LF、`_` 前缀私有字段） |
| NFR-6 | 合规 | 素材授权清晰 | 第三方素材在素材台账与 `THIRD-PARTY-NOTICES.md` 登记 |
| NFR-7 | 兼容 | 不改 ProjectSettings | 前后关系用 sortingOrder，不新增 Layer/Tag |
| NFR-8 | 健壮 | 素材异常不崩 | 贴图不可读/精灵缺失时降级而非抛异常 |

## 五、与第一阶段进度计划的对应

立项书第一阶段（2026 年 6–7 月）的六项任务与本文件的对应关系：

| 立项书任务 | 本阶段产出 | 对应需求 |
|---|---|---|
| ① 市场调研与分析 | 已形成三个短板的对比结论 | 第一节 |
| ② 需求分析与功能定义 | **本文档** + 系统用例 | 全部 |
| ③ 2D 空战基础原型搭建（Unity 工程、精灵导入、飞行操控验证） | Unity 工程 + 一键搭建 + 飞行模型 | FR-1 / FR-2 / FR-8 |
| ④ 网络通信链路验证 | 未开始（第二阶段） | — |
| ⑤ 开发环境与协作规范 | 仓库规范 + 编译验证脚本 | FR-8.3 / NFR-5 |
| ⑥ 算法原型可行性验证（威胁评估 + A\*） | Core 层实现 + 67 项自检 | FR-5 |

**超出第一阶段计划、提前完成的部分**：武器系统、碰撞判定、雷达 HUD、
波次系统、程序化视差背景。这些本属第二阶段范围，提前做是因为它们是
「验证飞行操控」的必要上下文——没有敌人和武器，无法判断操控手感是否成立。

## 六、验收方法

| 层次 | 方法 | 位置 |
|---|---|---|
| 算法正确性 | 67 项自动断言（编译 + 真实执行） | `tools/unity-verify/验证.bat` |
| 编译正确性 | 按 Unity 程序集划分编译三遍 | 同上 |
| 玩法完整性 | 60 秒无头自动对战，断言「刷怪→开火→命中→击落→计分→清波→推进波次」 | `CoreSelfTest.IntegrationTests` |
| 手感与表现 | 人工试玩 | [用户手册](../04-manuals/用户手册.md) 第二节 |
| 核心机制演示 | 按 F2 查看威胁网格 | FR-5.9 |
