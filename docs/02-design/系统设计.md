## 一、总体架构

第一阶段交付的是**单机客户端**，但目录结构按立项书的最终形态搭好了。

```
dogfight-threat-ai/
├── src/client/DogfightThreatAI/     Unity 客户端 ← 本阶段
├── src/server/GatewayServer/        网关服（第二阶段）
├── src/server/LogicServer/          逻辑服（第二阶段）
└── src/shared/Protocol/             共享协议（第二阶段）
```

### 客户端内部分层

```
┌──────────────────────────────────────────────────────────┐
│  View 层（MonoBehaviour）                                 │
│  PlaneView / SpritePool / ParallaxBackground /            │
│  TerrainTextureFactory / SpriteBank / HudOverlay          │
│  职责：只读仿真状态 → 画出来。绝不回写。                     │
├──────────────────────────────────────────────────────────┤
│  Gameplay 层（MonoBehaviour）                             │
│  GameDirector / GameBootstrap / PlayerInputSource /       │
│  CameraFollow / SpritePool                                │
│  职责：喂输入、按固定步长推进仿真、把仿真事件翻译成表现。       │
├──────────────────────────────────────────────────────────┤
│  Core 层（纯 C#，零 UnityEngine 依赖）★                    │
│  Simulation / FlightModel / PlaneState / ProjectileState  │
│  ThreatAssessment / ThreatField / Pathfinding /           │
│  AiBehaviors / AiController / MathUtil / DogfightConfig    │
│  职责：一切游戏规则与状态。可独立编译、独立测试。              │
└──────────────────────────────────────────────────────────┘
```

### 数据流（一帧）

```
Input(键鼠) ──> PlayerInputSource ──> PlaneIntent ─┐
                                                    ├─> Simulation.Step(dt)
AI 决策     ──> AiController ───────> PlaneIntent ─┘        │
                                                            ├─> SimEvent 列表
                                                            │        │
                        Simulation 状态（Planes/Projectiles）┘        │
                                    │                                │
                                    ▼                                ▼
                            View 层同步 Transform            特效池播爆炸/尾迹
                                    │
                                    ▼
                            HudOverlay（IMGUI）读 Simulation 状态
```

**关键约束：视图层只读仿真状态。** 这条约束是第二阶段网络同步能低成本落地的前提。

## 二、Core 层：为什么必须与引擎解耦

`Dogfight.Core.asmdef` 里设了 `noEngineReferences: true`，
**Unity 编译期就会强制** Core 不能 `using UnityEngine`。

带来三个直接好处：

| 好处 | 说明 |
|---|---|
| **可测试** | Core 能在 Unity 之外逐帧跑。`tools/unity-verify` 用编辑器自带的 Roslyn + mono 编译并执行，67 项自检全在这里 |
| **可上服务器** | 立项书要求「逻辑服务器集中管理、服务器权威」。仿真已经是一块独立的纯逻辑，搬到逻辑服只需换掉输入来源与输出目标 |
| **编译快、冲突少** | Core 单独一个程序集，改 View 不会重编 Core |

### 单位约定

仿真内部**统一用像素**：战场 3600×2600 px、速度 520 px/s。
只在视图层除以 `PPU = 32` 换算成世界单位。

理由：像素数值和策划案、算法论文里的数字能直接对齐；
而 Unity 侧要保持 PPU=32 的像素画规范（见[美术规范](美术规范.md)）。
换算集中在 `DogfightConst.PxToWorld()` 一个地方。

### 固定步长

仿真以 **1/120 秒**固定步长推进，在 `GameDirector.Update()` 里用累加器补步：

```csharp
_accumulator += Mathf.Min(Time.deltaTime, 0.25f);
int steps = 0;
while (_accumulator >= SimStep && steps < MaxStepsPerFrame) {
    Sim.Step(SimStep);
    _accumulator -= SimStep;
    steps++;
}
```

- 与渲染帧率解耦 → 不同机器上战斗结果一致（可复现的基础）；
- 单帧最多补 6 步、单帧最大计入 0.25 秒 → 避免卡顿后的「死亡螺旋」。

## 三、核心模块设计

### 3.1 飞行模型 `FlightModel`

```
油门 → 推力沿机头方向
惯性 → 速度是状态量，收油门靠阻尼减速，不会立刻停
转向 → 角速度受阻尼约束（松杆回中）；舵效 = clamp(speed / 150, 0.28, 1)
边界 → 速度夹在 [minSpeed, maxSpeed]；低于最小速度时"托举"回可操控速度
```

关键式：

```
authority   = clamp(speed / MinTurnAuthoritySpeed, TurnAuthorityFloor, 1)
targetAngVel= turnInput × TurnRate × authority
angVel      = damp(angVel, targetAngVel, AngularDamping, dt)     ← 转向阻尼
thrust      = throttle × MaxThrust
drag        = DragLinear × v + DragQuadratic × |v| × v
```

二次阻尼决定极速：`MaxThrust = DragLinear×v + DragQuadratic×v²` 的根约 523 px/s，
与配置的 `MaxSpeed = 520` 吻合。

### 3.2 威胁评估 `ThreatAssessment` ★

立项书核心。**单目标威胁值**由五个归一化因子加权求和：

| 因子 | 权重 | 含义 |
|---|---|---|
| 距离 | 0.34 | 越近越危险 |
| 相对方位 | 0.22 | 对方机头指向我方的程度 |
| 闭合率 | 0.16 | 距离正在缩小的速度 |
| 武器威胁 | 0.18 | 是否进入对方射程/包线，是否已被锁定 |
| 我方状态 | 0.10 | 血量越低、被弹越多，同一目标越致命 |

输出 `0..1`，并返回**完整分解** `ThreatResult`（含每个因子的值），
便于 HUD 显示与论文截图。

**场景整体威胁**取威胁最高的三个目标加权合并（100% / 45% / 20%）。

### 3.3 威胁网格 `ThreatField` ★

把战场切成 `Cell × Cell`（默认 100 px）的格子，每帧：

1. **衰减**：`v *= exp(-Decay × dt)`；
2. **累加**：敌机（半径 420 / 权重 1.0）、导弹（300 / 3.2）、子弹（130 / 0.55）、
   边界（260 / 0.8）按半径线性衰减累加，只遍历半径内的格子；
3. **采样**：双线性插值，避免 AI 抖动；
4. **梯度**：中心差分，规避时沿梯度下降方向飞。

复用为**侦察覆盖图**（`scanned`）供 BFS 找未侦察空域。

### 3.4 路径规划 `Pathfinding` ★

| 规划器 | 用途 | 算法 |
|---|---|---|
| `astar` | 追击与低风险规避 | A\*，8 邻域，代价 = 步长 × (1 + 威胁惩罚 × 归一化威胁)，禁止穿对角线缝隙，出路径后做视线抽稀 |
| `bfs` | 目标搜索与区域巡逻 | BFS 找最近的未侦察格子，高威胁格不通 |
| `steering` | 新兵档/规划失败的兜底 | 直接朝目标点飞 |

通过 `Pathfinding.Register(name, fn)` 注册，
**第二阶段接遗传算法只需再注册一个实现，行为代码一行不改**。

规划失败（返回 null）时有兜底：规避行为退化为「朝安全点直飞」。

### 3.5 AI `AiController` + `AiBehaviors` ★

严格的三层结构：

```
感知层  Perceive()   每帧：威胁评估 + 弹幕覆盖 + 是否被导弹锁定
决策层  Decide()     每 ReactionTime 秒：选交战目标、切行为模式
执行层  Execute()    每帧：行为产出 Desire → 合成 PlaneIntent
```

**模式切换带滞回**，避免在阈值附近抖动：

```
enter = min(profile.EvadeThreshold, EvadeEnter + (1 - profile.EvadeThreshold) × 0.5)
exit  = min(enter - 0.05, EvadeExit)
当前是规避 → 威胁 < exit 且血量 > 18% 才退出
否则       → 威胁 > max(enter, EvadeExit) 才进入（低血时更早进入）
```

五种行为只输出 `Desire`（航路点 / 瞄准目标 / 油门 / 开火 / 导弹），
由控制器统一合成转向指令，并叠加：

- **瞄准误差**：平滑随机游走（`Damp`），不是每帧乱跳；
- **点射**：开火切成 0.5~0.85 秒的短点射；
- **失速保护**：速度过低强制加油门；
- **大角度转向收油**：避免高速失位。

### 3.6 战斗仿真 `Simulation`

一个类装下全部规则：实体表、武器冷却/过热/装填、导弹锁定、
扫掠碰撞、撞机、伤害与击落、波次生成、复活、计分、连击。

**与视图的接口是事件列表**：仿真产出 `SimEvent`（爆炸/命中/尾迹/击落/波次…），
`GameDirector` 每帧 `DrainEvents` 后翻译成特效。
这样仿真里不出现任何 `GameObject`、`Sprite`、`AudioClip`。

### 3.7 碰撞

**不用 Unity 物理，全部手算圆-圆与扫掠**。理由：

1. 弹丸速度最高 1020 px/s，在 1/120 步长下一步移动 8.5 px；
   用「上一帧位置 → 当前位置」的线段与目标圆求交，**不会穿透**；
2. 不依赖 Layer / Tag / 物理矩阵，因此**不需要改 ProjectSettings**；
3. 规则集中在 Core，服务器权威计算时可以直接复用同一份判定。

## 四、View 层设计

### 4.1 素材台账 `SpriteBank`

ScriptableObject，由编辑器菜单用 `AssetDatabase` 从
`Assets/ThirdParty/kenney-pixel-shmup/` 自动填好，运行时只查表。

好处：素材仍住在 `ThirdParty/`（符合 [NOTES.md](../../art-source/third-party/kenney-pixel-shmup/NOTES.md) 的导入约定），
不需要为了运行时加载把它们复制一份到 `Resources/`。

取不到时**退化为程序化生成的三角占位图**，保证素材没配好时游戏仍能跑。

### 4.2 程序化地表 `TerrainTextureFactory`

运行时把图块拼成一张 1024×1024 的**无缝**地表贴图：

1. 随机撒岛屿圆盘 → 掩码平滑（去细碎 / 填小洞）；
2. 撒沙地斑块（只落在陆地上）；
3. 按「水在哪一侧」选 8 向边缘砖铺地；
4. 实心格上随机点缀树木/房屋；
5. 输出为 `wrapMode = Repeat` 的 Texture2D，交给 `SpriteRenderer` 的 Tiled 绘制模式。

**无缝性**：岛屿掩码、边缘判定、点缀位置全部按 N 取模环绕，
所以贴图可直接无限平铺，不需要额外做接缝补偿。

失败（贴图没勾 Read/Write）时返回 null，退化为纯色海面。

### 4.3 多层视差 `ParallaxBackground`

每层是一个 Tiled 模式的 `SpriteRenderer`，每帧把图层位置设为
`相机位置 × parallax`：相机移动 1 个单位，图层只移动 `parallax` 个单位。

| 图层 | parallax | sortingOrder |
|---|---|---|
| 海面/地表 | 0.30 | −200 |
| 海涌 | 0.42 | −199 |
| 云层 | 0.62 | −100 |

不写 Shader，不依赖自定义材质。

### 4.4 HUD `HudOverlay`

用 IMGUI（`OnGUI`）绘制。**这是个刻意的取舍**：
IMGUI 不需要任何字体资源、Canvas、EventSystem 或 TMP Essentials 导入，
**不会因为素材没配好而白屏**。代价是表现力一般。
第二阶段换 uGUI + TMP 时，数据接口（读 `Simulation`）不用变。

包含：血量/油门/空速/机炮过热/导弹弹药面板、波次与敌机数、得分与连击、
FPS、三层环形雷达（含扫描线与来袭导弹告警）、威胁条、低血边框告警、
被锁定告警、出界告警、结算面板，以及 **F2 威胁网格叠加视图**。

## 六、演进路线（第二阶段）

立项书要求「客户端—网关—逻辑服务器」三层架构 + 服务器权威。

已经为此做好的准备：

1. **仿真与渲染已彻底隔离**。`Simulation` 不引用任何引擎类型，
   搬到逻辑服只需换掉输入来源（网络消息）与输出目标（网络广播）。
2. **固定步长 + 可复现**。`Simulation` 用显式的 `MathUtil.Rng(seed)`，
   同种子同输入 → 同结果，这是状态同步与回放的基础。
3. **输入已经抽象成 `PlaneIntent`**。玩家与 AI 走同一条通道，
   网络层只要把远端玩家的 `PlaneIntent` 喂进同一个 `Simulation` 即可。
4. **规划器与行为都是注册表**。新增算法不改动现有代码。

需要新增的：

| 模块 | 位置 | 说明 |
|---|---|---|
| 协议定义 | `src/shared/Protocol/` | 消息结构 + JSON Schema，两端共用 |
| 网关服 | `src/server/GatewayServer/` | 连接认证、房间管理、消息路由 |
| 逻辑服 | `src/server/LogicServer/` | 权威仿真（直接复用 Core）、广播状态快照 |
| 客户端网络层 | `src/client/.../Net/` | 发送 `PlaneIntent`、接收快照、对本地玩家做预测与插值 |
| 遗传算法 | `Core/Pathfinding.cs` | `Register("ga", fn)` 用于复杂态势下的攻击目标选择与规避路径优化 |
| 轨迹回放 | 客户端 | 记录 `PlaneIntent` + 种子即可完整重放（仿真是确定性的） |
